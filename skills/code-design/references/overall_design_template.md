# ［システム名］全体設計書

## 1. 目的

［誰が、何のために利用し、どのような結果を得るシステムかを記載する。］
［対象とする業務と、今回追加または変更する範囲を記載する。］

前提条件：［利用環境、外部システム、運用上の制約］
関連要件：［要件を確認できる資料のパスと該当節］
既存仕様：［追加実装の基準となる資料またはソースのパスとリビジョン］

追加または変更する箇所は、図のノードや区間をオレンジで示し、文章、表、矢印のラベルには★を付ける。

```mermaid
flowchart TD

    subgraph server["［サーバーと実行環境］"]

    end
    external["［外部システム］"]
    user -->|"［操作］"| ui
    ui -->|"［通信方式と用途］"| application
    application -->|"★［通信方式と用途］"| worker

    worker -->|"［通信方式と用途］"| external

```

［ノードを実際の構成要素に置き換え、実行単位と配置場所を示す。接続線には通信方式と用途、または共有データを記載する。］

| 構成要素 | 責務 | 起動と終了 |
| --- | --- | --- |
| ［画面またはプロセス名］ | ［担当する処理と管理する情報］ | ［誰が、いつ起動し、いつ終了させるか］ |

［複数の構成要素で利用するデータについて、管理元と受渡し先を記載する。］

## 3. 全体の動作

### 3.1 ［一連の業務または利用場面］

［開始の契機、実行に必要な前提、完了時に得られる結果を記載する。］

```mermaid
sequenceDiagram
    actor User as ［利用者］
    participant UI as ［操作画面］
    participant Application as ［受付プロセス］
    participant Worker as ［実行プロセス］
    User->>UI: ［開始操作］
    UI->>Application: ［要求名と主な入力］
    rect rgb(255,243,224)
        Application->>Worker: ★［処理要求と主なデータ］
    end
    Worker-->>Application: ［受付結果］
    Application-->>UI: ［受付結果］
    Worker-->>Application: ［完了通知と結果］
    Application-->>UI: ［状態と結果の更新］
    UI-->>User: ［完了表示］
```

［実際の連携に合わせて、同期応答、非同期通知、待合せ、人による確認を区別する。受付と処理完了の関係も明記する。］
［業務の流れが異なる場合は節を分ける。個々の操作条件とデータ形式は、6章の機能仕様書を参照する。］

## 4. 状態管理と停止・復旧

### 4.1 全体の状態

管理対象：［処理単位、セッション、システム全体など］
管理元：［状態を管理し、他の構成要素へ通知するプロセス］

```mermaid
stateDiagram-v2
    state "［待機状態名］" as Ready
    Ready : ［必要な初期化］が完了し、新しい処理を受け付けられる状態
    Ready : 受付可能な操作：［開始操作名］
    state "［実行状態名］" as Running
    Running : ［対象の業務］を実行し、関連する構成要素の処理完了を待っている状態
    Running : 受付可能な操作：［中止操作名］
    state "［終了処理状態名］" as Finishing
    Finishing : ［結果］が確定し、［後処理］の完了を待っている状態
    Finishing : 受付可能な操作：［操作名または受付可能な操作がある状態への移行条件］
    state "［復旧待ち状態名］" as Recovery
    Recovery : ［異常］を検出し、［復旧条件］の成立を待っている状態
    Recovery : 受付可能な操作：［復旧操作名］
    [*] --> Ready: ［初期化完了条件］
    Ready --> Running: ［開始要求と成立条件］
    Running --> Finishing: ［正常終了または通常中止の条件］
    Finishing --> Ready: ［後処理完了条件］
    Running --> Recovery: ［異常の検出条件］
    Finishing --> Recovery: ［後処理失敗の条件］
    Recovery --> Ready: ［復旧操作と成立条件］
```

［対象システムで管理する状態と遷移に置き換える。各状態の枠内には、成立している事実と受付可能な操作を記載する。］
［機能内部の状態は、対応する機能仕様書を参照する。］

### 4.2 停止と復旧の分担

| 事象 | 検出元と判断主体 | 各構成要素の処理と順序 | 状態とデータの扱い | 復旧条件と操作 |
| --- | --- | --- | --- | --- |
| ［通常完了］ | ［完了を検出し判断する構成要素］ | ［結果通知、保存、終了などの順序］ | ［遷移先と保持するデータ］ | ［次の処理を開始できる条件］ |
| ［利用者による中止］ | ［操作の受付元と判断主体］ | ［中止要求、停止、後処理の分担］ | ［途中結果と未処理要求の扱い］ | ［再実行または次の処理への移行条件］ |
| ［システム全体に影響する異常］ | ［異常の検出元と判断主体］ | ［停止対象、通知先、停止順序］ | ［遷移先と保持または破棄するデータ］ | ［確認担当者、確認内容、復旧操作］ |

［通信断、プロセス終了、タイムアウトなど、複数の構成要素に影響する事象を記載する。］

| 通信元 | 通信先 | 通信方式 | IF名または接続先 | 用途と主なデータ | 定義先 |
