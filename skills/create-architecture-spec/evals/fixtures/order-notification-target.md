# 移行要件

- イベント名は `OrderConfirmed.v1` とする。
- payloadは現行HTTP本文と同じ3項目を維持する。
- Order Serviceはoutboxへ注文と同じトランザクションでイベントを書き込む。
- publisherは少なくとも1回配信する。順序保証はない。
- Notification Serviceは `eventId` で冪等に処理する。
- 処理失敗は最大5回、指数バックオフで再試行し、その後DLQへ移す。
- DLQは14日保持し、運用者が原因修正後に再投入できる。
- 移行は、イベントのshadow配信、HTTPとイベントの二重実行、イベント単独、旧HTTP削除の4段階で行う。
- 二重実行中も利用者へ通知を1回だけ送る。
- 各段階は7日間、通知欠落率0.01%未満かつ重複通知0件の場合だけ次へ進む。
- 基準を満たさない場合は直前段階へ戻す。
- broker製品と監視製品は未決定である。
