# 仕様書の日本語品質

内容を確定してから文章を推敲する。読みやすさのために仕様を変えない。

## 保持するもの

推敲前後で、次を同じに保つ。

- 主張と優先順位
- 必須、推奨、任意、禁止の強さ
- 条件、例外、否定、数量、順序、期限
- 動作主体、対象、責任範囲
- As-Isの事実、To-Beの判断、仮定、未決事項の区別
- 要件ID、根拠ID、Decision Logの対応

コードブロック、Mermaid構文、JSON、パス、識別子、引用値、契約値は保護する。自然言語を含む見出し、本文、図の説明、表の説明欄は推敲してよい。表のID、型、数値、列挙値は変えない。

## 直すもの

- 主語と述語、条件と結果、修飾語と対象の対応を明確にする。
- 「解像度を上げる」「安全側に倒す」「静かに壊れる」など、意味を取り違えやすい比喩を具体的な表現へ直す。
- 内容のない予告、過剰な太字、絵文字、煽り、読了効果、定型的な結びを削る。
- 独立した規則や対応関係は箇条書きに残す。箇条書きの比率だけを理由に地の文へ戻さない。
- 同じ内容の反復を削る。ただし、複数対象を区別するための再掲は残す。
- 未知の主体、原因、便益、条件、数値を補わない。

## 検査手順

1. 推敲前のドラフトを一時ファイルへ保存する。
2. 全自然言語を推敲する。
3. `yomiyasu_lint.py` の警告を全件確認する。
4. `yomiyasu_diff.py` で追加・削除・文末・構造の変化を確認する。
5. 保護対象、ID参照、Markdown、Mermaidを再検証する。

警告は見直し候補であり、警告ゼロを合格条件にしない。残す警告には、専門用語、正確な技術表現、必要な比較などの理由が必要である。
