# Quality Gates

## 1. 正確性

- 重要なAs-Is記述に `E-*` がある。
- 根拠は実際に読んだコード、設定、要件、利用者回答である。
- 推測したAPI、テーブル、担当、数値、原因がない。
- To-Beの判断とAs-Isの事実が区別されている。

## 2. 追跡性

- `FR-*`、`NFR-*`、`CON-*` の参照先が存在する。
- `E-*` は出典、確認内容、シンボル、リビジョンへ対応する。
- `D-*` は選択肢、採用理由、影響、関連要件を持つ。
- `A-*` と `Q-*` には影響と解決条件がある。
- API、データ制約、処理規則、失敗処理、検証条件から関連要件または設計判断を直接参照できる。

## 3. 設計の完結性

- 基本設計に構成図と主要シーケンス図がある。
- システム境界、データ所有、信頼境界が分かる。
- 関連する品質特性に測定または検証方法がある。
- 詳細設計では、該当する契約、境界値、失敗、再試行、並行性、移行、検証条件が決まっている。
- 対象外の章や図を埋めるための架空仕様がない。
- 根拠のない文字数、件数、時間、回数、保持期間、閾値、列挙値がない。
- 要件資料の各項目に個別の根拠IDがあり、包括的な1件の根拠だけで代用していない。
- 成果物内の規範値を監査し、同じ対象について要件またはAs-Is根拠が示した値だけを残している。
- 冪等再送、同時実行、重複、部分失敗、エラー本文の構造が、Decision Logまたは要件によって確定している。
- `Q-*` は利用者判断や規範値が必要な部分に限定され、構造的な振る舞い全体を未決にしていない。
- 未決事項の担当は根拠から特定できる名前だけを使い、根拠がなければ `未定` になっている。
- 冪等な完了済み要求は、変動する外部状態の再評価より先に保存済み結果を返す。

## 4. 文章品質

- 主体、対象、条件、例外を一度で追える。
- 曖昧な比喩、過剰な装飾、内容のない前置きがない。
- 推敲によって主張、条件、数量、断定強度、責任主体が変わっていない。
- lint警告を全件確認し、残す理由を検査記録に残した。

## 5. 構文

- Markdownの見出し階層、表、コードフェンスが閉じている。
- Mermaidを解析できる。
- コード、JSON、パス、識別子、ID、引用値、契約値が推敲前後で変わっていない。
- テンプレート説明、内部メモ、`[ASK USER]` が残っていない。
